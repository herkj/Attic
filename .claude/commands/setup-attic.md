# /setup-attic

Set up Attic and create the Research vault structure. Run this once after cloning.

## Steps

### 1. Find Attic's location

Glob for the setup-attic.md file itself to find the Attic root. The Attic root is the folder containing `.claude/`.

### 2. Ask where to create the vault

Use AskUserQuestion with two options:
- "Use the default location: `{attic-parent}/Research/`" (recommended)
- "Specify a custom path"

If the user picks the default, proceed with `{attic-parent}/Research/` as the vault root.
If the user picks custom, ask them to type the full path and wait for their input.

### 3. Create folder structure

Create these folders (use Bash mkdir -p):
- `{vault}/inbox/`
- `{vault}/inbox/processed/`
- `{vault}/Studies/`
- `{vault}/Reports/`
- `{vault}/Repository/`
- `{vault}/config/taxonomy/`

Confirm each folder was created.

### 4. Ask about domain taxonomy

Use `AskUserQuestion`: "Do you want to set up a domain-specific taxonomy? This helps Attic tag your research with terms from your own product area."
- **Yes - generate from websites** - I'll fetch your product/company sites and propose a taxonomy
- **No - core taxonomy only** - I'll skip domain tags for now (you can add them later)

If "No": skip to step 6.

### 5. Generate custom taxonomy from websites

Ask:

> What would you like to name this taxonomy file? This name helps identify it when you have multiple taxonomies. (e.g. "consumer-app", "internal-tools", "mobile")

Store as `{taxonomy_name}`. The file will be saved as `{taxonomy_name}.yaml`.

Then say:

> Share any relevant websites - your product, your company, your industry. Paste URLs or names, one per line.

For each URL provided:
- Use the `defuddle` skill to fetch and extract clean content
- If a name is given instead of a URL, use WebSearch to find the main website first

Analyze the extracted content to identify:
- **Product Areas** - the main product categories, features, or service areas in this domain
- **Topics** - recurring themes, use cases, user journeys, or problem areas
- **External Entities** - competitors, partners, regulators, or third parties mentioned

Generate a taxonomy file in this format:

```yaml
# {taxonomy_name} taxonomy - generated by /setup-attic
# Edit this file anytime. Commit it to share with your team.

product_areas:
  - name: "Example Area"
    aliases:
      - example-area
      - alternate-spelling

topics:
  - name: "Example Topic"
    aliases:
      - example-topic

external_entities:
  - name: "Example Entity"
    aliases:
      - example-entity
```

Show the full draft to the user. Then use AskUserQuestion with two options:
- "Looks good - save it" (recommended)
- "I want to make changes"

If "Looks good", save to `{vault}/config/taxonomy/{taxonomy_name}.yaml`.
If "I want to make changes", ask what to change, apply the edits, show the updated draft again, and repeat until approved.

### 6. Summary

Show what was created (vault path, folders, whether custom taxonomy was generated).

Then say:

> **Attic is ready.**
>
> Attic is a human-in-the-loop AI research assistant. It's built to help you make sense of user interviews. AI extracts observations and synthesises insights - but you review and approve each step. Every observation traces back to a quote. Every insight links to the observations it came from.
>
> **Each interview is a session.** A session can have multiple source files - a transcript, your own notes, observer notes from a colleague. `/analyse` asks what type of source you're working with and runs the appropriate extraction pipeline. You can add more sources to a session later by running `/analyse` again on the session file.
>
> **The standard workflow:** Drop source files in `{vault}/inbox/` → `/analyse` to extract observations → `/review-observations` to approve, reject, edit, or add your own observations → `/synthesize` to turn them into insights. Reports and articles use the same `/analyse` entry point - just select "Report or article" as the source type.
>
> **Sharing with your team:** The `{vault}/config/taxonomy/` folder is designed to be committed to a shared git repository alongside your research data. When a team member adds or refines a tag, everyone picks it up on the next pull.
>
> **Any language, any region - no setup needed:** Attic auto-detects and preserves the language of every source file and never translates. Participant pseudonyms are generated per participant to fit their region, so there are no name lists to maintain. You can optionally set a `language` hint per study.
>
> Once you have multiple sessions, run `/study-synthesize` to find patterns across all of them and answer your research questions.
>
> **If you want to skip the review step:** `/analyse` asks "Manual or Yolo?" upfront. Pick **Yolo** to run the full pipeline automatically (extract → auto-approve → synthesize) - you only choose which study to assign the session to.
>
> **Next step:** Drop an interview file or report URL in `{vault}/inbox/` and run `/analyse`.
